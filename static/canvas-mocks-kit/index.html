How to find what you need across these 70 SDC pages.

Find an SDC fast

  • ⌘+K (or /) opens the command palette. Type any part of the SDC id, title, alias, or props — both parents and slot children match.
  • Sidebar tree on the left groups SDCs by author-facing category (Site shell pinned top, Slot children pinned bottom).
  • Filter input above the tree narrows the list as you type — searches id + title + aliases + props.
  • Recent SDCs surface at the top of the palette so the most-touched components stay one keystroke away.

Read a per-SDC page

  • Default — canonical fixture rendered at desktop width. The iframe shows the actual rendered twig output.
  • Devices · N — same fixture × every viewport (mobile / tablet / desktop / large_desktop) with the schema's region grid below each frame.
  • Variations · N — cartesian gallery of every variation × background combo declared in the schema enums.
  • Slot children · N — full props schema for every direct child SDC (always visible — slot contracts are first-class info).
  • Props + More views — schema table + extra-page links (dev-view only).

Inspect slot children

  • Children appear nested under their parent in the sidebar (organism children) or in the dedicated Slot children group at the bottom (chrome children — y-footer-link, y-header-cta, etc.).
  • Each child has its own page rendered inside a 1-item parent shell so you see the surrounding chrome (frame chevron, accordion wrapper, grid column) — not a naked element.
  • Multi-parent children appear under every parent that slots them; the "Used by" row on the child page lists all of them.

Use the JSON index

  • Every SDC's metadata lives at one endpoint: https://ds-docs.y.org/canvas-mocks-kit/mocks-index.json
  • Each entry carries id, title, category, bundle code, props list, children array, parents array, and the bundle-icon SVG glyph.
  • Useful for batch tooling: scripts that audit, compare, or generate code from the schema set.

Catalog: ds-docs.y.org/canvas-mocks-kit/ · JSON index: /mocks-index.json.

Using these mocks in your project click to expand

Workflows for the five most common roles consuming this catalog.

Drupal SDC theme port

  • The frame iframe on every SDC page is the visual ground truth: same twig template renders here as in production.
  • If your Drupal render does not match the frame, the divergence is in your theme — not in the mock. The Props tab carries the schema your theme must accept.
  • Pair-check with the live production demo at small-y-stable.y.org/demo-ui-kit when an SDC reads ambiguous.

WordPress Timber port

  • The same .twig source files that render this catalog also drive the WordPress canvas-wp port via Timber. Drop them in unchanged.
  • Replicate the fixture shape shown in the Default tab — your Timber test should pass the same data and produce the same DOM.
  • Slot children pages document the per-child schema; Timber loops feed the same prop names.

React / Edge consumer

  • The Slot children section + the Props tab together form a props interface contract.
  • Use them as the source for TypeScript / Zod / JSON Schema types when porting an SDC to a JSX renderer.
  • Variations enums map directly to discriminated-union props (e.g. variation: 'standard' | 'color' | 'overlay' | 'chevron').

Designer / PM speccing

  • Copy the deep frame URL into your ticket — /canvas-mocks-kit/y-cards/frame-chevron.html beats a screenshot because it stays in sync with code.
  • Pair every spec with the live production render at small-y-stable.y.org/demo-ui-kit as a side-by-side reference.
  • The Variations gallery surfaces enum combos production may never hit — useful for edge-case acceptance criteria.

Reviewer

  • Walk the sidebar by category. Site shell up top, Slot children at the bottom — everything in between is grouped by author-facing labels.
  • File feedback against deep URLs: <sdc>/index.html#variations, <sdc>/y-lb-demo-mapping.html, or a specific frame.
  • The frame iframe is the single visual reference — if it looks wrong, write the bug from the frame URL.

Live production render: small-y-stable.y.org/demo-ui-kit · Catalog reference: https://ds-docs.y.org/canvas-mocks-kit/<sdc>/index.html.

Using these mocks with agents click to expand

Every page on this catalog is reachable as a stable public URL — feed those URLs into Claude Code, GitHub Copilot, or any agent runtime that supports web fetch. No source repo access needed.

Fetch a per-SDC page

Pull canonical render + schema in one request. The HTML carries an inlined __MOCKS_INDEX with full metadata for every SDC.

WebFetch https://ds-docs.y.org/canvas-mocks-kit/y-cards/index.html

Returns the rendered overview + Props table + Slot children section + a JSON snapshot. Use as ground truth before generating downstream code.

Read the JSON index

All SDC metadata in one endpoint — bypass the HTML when you only need structure:

curl https://ds-docs.y.org/canvas-mocks-kit/mocks-index.json \
  | jq '.[] | select(.kind=="parent") | .id'

Returns ids, props, children arrays, categories, bundle codes for every parent + slot child. Pipe into prompts for batch analysis.

Compare mock vs production

Pair every catalog frame with the live demo for parity checks. Agent prompt:

Compare these two renders:
  https://ds-docs.y.org/canvas-mocks-kit/y-hero/frame-promo.html
  https://small-y-stable.y.org/demo-ui-kit (scroll to y-hero)
Report visual differences.
